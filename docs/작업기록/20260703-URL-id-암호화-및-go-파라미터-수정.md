# Kanto GO 상세 URL 파라미터 수정 + 전체 서비스 id 암호화

브랜치: `fix/532-url`

## 배경 / 문제

1. `/go`에서 모임을 클릭해도 URL이 갱신되지 않는 버그가 있었다. `/go`는 지도가 항상 떠 있고 상세는 그 위 사이드 패널로 열리는 구조인데, 클릭 핸들러가 React state(`selectedMeetupId`)만 바꿀 뿐 `router.push`/`history` 갱신이 전혀 없어서 새로고침하면 패널이 사라지고 링크 공유도 불가능했다.
2. 프로필 페이지의 모임 목록은 `/go/${id}`로 링크를 걸고 있었는데 그 경로를 받아줄 `app/(user)/go/[id]/page.tsx` 자체가 없어 404였다.
3. 위 버그를 고치면 모임 id(순차 정수 PK, `posts.id`)가 URL에 그대로 노출되는데, 이 참에 중고거래/구인구직/부동산/유저 프로필/채팅까지 전체적으로 id 노출을 암호화하기로 범위가 확장됨.

## 작업 내용

### 1. `/go` URL 파라미터 동기화 (쿼리스트링 방식)

- `/go`는 지도가 마운트된 채 유지돼야 하므로 동적 라우트(`/go/[id]`) 대신 **쿼리스트링**(`/go?m=<토큰>`)으로 처리. `router.push` 대신 `window.history.replaceState`를 직접 써서 Next.js 서버 컴포넌트 재요청(RSC round-trip) 없이 주소창만 갱신하도록 함.
- `GoClient.tsx`: 모임 선택 시 URL에 토큰 반영, 공유 링크(`?m=`)로 진입 시 최초 1회 해당 모임 상세를 복원(`getMeetupByToken`, 로드된 목록에 없는 모임은 서버에서 추가 조회).
- `ProfileMeetingsSection.tsx`: 존재하지 않던 `/go/${id}` 링크를 `/go?m=${id_token}`으로 교체.

### 2. id 암호화 기반 구축 (AES-256-GCM)

- `src/utils/idCipher.ts`: 공용 암복호화 코어. `ID_ENCRYPTION_SECRET`(64자리 hex, `.env.local`에 추가) 키로 AES-256-GCM 사용, 도메인 문자열을 AAD(추가 인증 데이터)로 묶어서 같은 키를 써도 `post`/`user`/`chat` 토큰끼리 서로 교차 복호화되지 않도록 함.
- 도메인별 얇은 래퍼: `postIdCipher.ts`(게시글 — 중고거래/구인구직/부동산/모임이 전부 `posts.id`를 공유), `userIdCipher.ts`(유저), `chatIdCipher.ts`(채팅방).
- 각 래퍼는 `encryptXxxId`/`decryptXxxId` 외에 `resolveXxxId`(토큰이면 복호화, 아니면 평문 숫자로 해석)를 제공 — **기존에 공유된 평문 링크·DB에 저장된 평문 id(알림 등)가 계속 동작하도록 하는 하위호환 레이어.**

### 3. 중고거래/구인구직/부동산 — 게시글 id 암호화

- 목록 서비스(`getUsedGoodsList`, `getJobList`/`getPopularJobs`, `getRentalList`)가 각 항목에 `id_token`을 포함해서 반환.
- 상세 페이지(`[id]/page.tsx`)는 `resolvePostId`로 토큰/평문 id를 모두 받고, 판매자/작성자 정보에 `id_token`(유저 암호화)을 붙여서 하위 컴포넌트로 전달.
- 목록 카드, 상세 페이지 내 관련 매물 캐러셀, 수정 링크, 판매자/작성자 프로필 링크, 메인 페이지 인기글 섹션(`Popular.tsx`)까지 전부 토큰 사용.
- `edit/page.tsx`, `metadata.ts`(OG 메타데이터/canonical URL)도 동일하게 `resolvePostId` 적용. `rental/[id]/page.tsx`의 `params.id` 타입이 원래 `number`로 잘못돼 있던 것도 함께 수정(`string`).

### 4. 유저 프로필 id 암호화

- `/user/[id]/page.tsx`, `metadata.ts`: `resolveUserId`/`encryptUserId` 적용.
- 게시글 상세에서 판매자/작성자 프로필로 이동하는 링크(중고거래/구인구직/부동산)는 3번 작업에서 이미 토큰 적용.

### 5. 채팅 관련 프로필 링크 암호화

- 채팅창 헤더에서 상대 프로필 클릭(`ChatHeader.tsx`): 기존 채팅방을 열 때는 `/api/chat/[id]/route.ts`가 `partner.id_token`을 계산해 내려주고, 새 채팅 시작 시에는 게시글 상세에서 이미 계산된 토큰을 `partner` 객체에 그대로 실어 보냄(`UsedGoodsDetail.tsx`/`JobAuthorInfo.tsx`/`RentSellerInfo.tsx`).
- 모임 그룹채팅 멤버 목록(`GroupMemberList.tsx`): 서버 액션 `getRoomMembers`(`services/go/groupChat.ts`)에서 각 참여자 `user_id`를 암호화해 `id_token`으로 내려주도록 수정.

### 6. 채팅방 자체 id 암호화 (`?chat=` 쿼리 파라미터)

- 채팅 위젯은 페이지 라우트가 아니라 `FloatingChatWidget.tsx`가 `history.replaceState`로 `?chat=<id>`를 직접 관리하고 있었음 — 이 부분이 평문 숫자로 노출되고 있었다.
- `services/chat/chat.ts`의 `getChatList`가 각 채팅에 `id_token` 포함, `/api/chat/[id]/route.ts`가 `resolveChatId`로 토큰/평문을 모두 받고 `chatIdToken`도 응답에 포함하도록 수정.
- `FloatingChatWidget.tsx`: 채팅방을 열면 `?chat=<토큰>`으로 주소창이 바뀌고, 토큰 URL로 새로고침해도 같은 채팅방이 복원되도록 수정(토큰이면 `/api/chat/${token}`을 먼저 호출해 실제 숫자 id를 받아온 뒤 그 id로 방을 염).

## 설계상 트레이드오프

- **평문 id도 계속 허용**(`resolveXxxId`가 토큰 실패 시 숫자로 폴백)하는 방식을 택함 — 기존에 공유된 링크, DB에 평문으로 저장된 알림 딥링크(`common_notifications.related_id`)가 깨지지 않게 하기 위함. 대신 `/usedgoods/1`처럼 순차 숫자로 직접 접근하는 것 자체는 막히지 않는다. 즉 이번 작업은 "기본적으로 노출되는 URL 형태를 가리는" 수준이며, 스캐닝/enumeration을 원천 차단하는 보안 조치는 아니다(사용자와 논의 후 확정한 방향).
- 토큰은 AES-GCM 특성상 같은 id라도 호출할 때마다 다른 문자열이 나온다(랜덤 IV). 같은 id를 가리키는 토큰이 여러 개 존재할 수 있으며 전부 유효하게 복호화된다 — 캐싱/비교 목적으로는 쓰지 않도록 주의.
- 내부 API 호출·서버 액션 인자(좋아요, 신고, 채팅 postId 등)는 계속 평문 숫자를 사용— 클라이언트가 어차피 해당 값을 이미 들고 있어야 하는 값들이라 암호화 실익이 없고, 변경 범위를 "브라우저 주소창에 보이는 URL"로 한정했다.

## 남아있는 범위 외 작업 (미암호화, 평문 폴백으로만 동작)

- 글쓰기/수정 완료 후 리다이렉트(`CreateUsedGoodsForm.tsx`, `RentalCreateForm.tsx`, `useCreateJobForm.ts`) — 작성자 본인만 보는 URL이라 우선순위 낮음으로 보류.
- 알림 딥링크(`src/utils/notification.ts`) — DB에 이미 평문 숫자로 저장된 `related_id`를 그대로 사용.
- 채팅 목록이 Supabase Realtime `INSERT` 이벤트로 클라이언트에서 직접 채워지는 극히 일부 케이스(`useChatListRealtime.ts`의 `handleInsert`)는 서버를 거치지 않아 그 순간엔 `id_token`이 없고, 다음 목록 갱신 때 토큰으로 교체됨.

## 검증

- `npx tsc --noEmit`, `npx eslint <변경 파일>` 전체 통과.
- Playwright로 실제 브라우저에서 확인:
  - `/go`: 모임 클릭 → `?m=` 토큰 반영 → 해당 URL로 새로고침 시 같은 모임 패널 복원 → 닫으면 파라미터 제거.
  - 중고거래/구인구직/부동산: 목록 → 상세 이동 시 토큰 URL, 평문 숫자 URL(`/usedgoods/438`)로도 정상 접근(하위호환), 판매자 프로필 링크·관련 매물 링크 모두 토큰.
  - 채팅: "채팅하기" → 채팅창 헤더 프로필 링크 토큰 확인, `?chat=` 파라미터가 토큰으로 바뀌는 것과 토큰 URL 새로고침 시 같은 대화방 복원 확인.

## 환경변수

- `.env.local`에 `ID_ENCRYPTION_SECRET`(64자리 hex, AES-256 키) 추가함. **배포 환경(Vercel 등)에도 동일한 값을 별도로 설정해야 프로덕션에서 정상 동작함** — 로컬 작업만으로는 대신할 수 없는 부분이라 별도 조치 필요.
