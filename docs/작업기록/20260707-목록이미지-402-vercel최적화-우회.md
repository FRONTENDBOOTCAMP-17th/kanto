# 목록 페이지 이미지 402 에러 해결 — Vercel 이미지 최적화 우회

- **날짜**: 2026-07-07
- **담당자**: 임태린
- **분류**: 핫픽스 / 이미지 렌더링 (Vercel 이미지 최적화 한도)
- **상태**: 완료
- **이슈**: #643
- **브랜치**: `hotfix/v1.3.3`

## 1. 배경 / 문제 정의

목록 페이지(`/usedgoods` 등) 진입 시 이미지가 렌더링되지 않고 콘솔에 402 에러가 발생.

관찰된 응답 헤더:

| 항목 | 값 |
|------|-----|
| Status Code | `402 Payment Required` |
| `x-vercel-error` | `OPTIMIZED_IMAGE_REQUEST_PAYMENT_REQUIRED` |
| 요청 경로 | `/_next/image?url=https%3A%2F%2F...supabase.co...webp&w=1080&q=75` |

## 2. 원인

- Next.js `<Image>` 컴포넌트는 Vercel의 **Image Optimization**(`/_next/image`)을 통해 이미지를 리사이즈·변환해서 내려준다.
- Vercel 무료(Hobby) 플랜은 이 최적화 이미지 변환 개수에 **월 한도**가 있고, 초과하면 402를 반환한다.
- 목록 페이지는 한 번에 여러 장의 썸네일(= 서로 다른 최적화 요청)을 불러오므로 한도를 빠르게 소모한다. 그래서 목록 페이지에서 먼저 402가 발생.
- Supabase 원본 이미지 자체 문제가 아니라, **브라우저 → Vercel 최적화 → Supabase** 경로의 중간(Vercel 최적화) 단계에서 막힌 것.

```
변경 전:  브라우저 → Vercel 최적화(여기서 402) → Supabase
변경 후:  브라우저 → Supabase (직접)
```

## 3. 조치 내용 (방법 A — Vercel 최적화 우회)

### `src/components/common/ImageWithFallback.tsx`

- 공통 이미지 래퍼 `ImageWithFallback`의 `<Image>`에 `unoptimized` 속성 추가.
- 이 래퍼는 목록 카드(`ContentCard`), 상세 이미지(`UsedGoodsDetail`), 캐러셀(`ImageCarresel`, `RelatedItemsCarousel`) 등 **사용자 업로드(Supabase) 이미지 전반의 공통 진입점**이므로, 한 곳 수정으로 402 발생 지점을 전면 제거.

```tsx
<Image
  {...rest}
  src={imgSrc}
  alt={alt}
  unoptimized
  onError={...}
/>
```

### 왜 화질/성능 손해가 거의 없는가

- Supabase 원본은 업로드 시점에 이미 **WebP + 긴 변 1600px 상한**으로 리사이즈되어 저장된다
  (참고: `docs/작업기록/20260703-supabase-이미지-트래픽-최적화.md`).
- 따라서 Vercel 최적화를 건너뛰어 원본을 직접 받아도 파일 크기·화질 차이가 미미하다.
- 원본이 이미 WebP이므로 포맷 변환 이득도 낮았다.

## 4. 기대 효과

- 목록/상세/캐러셀 등 사용자 업로드 이미지의 **402 에러 제거**.
- Vercel 이미지 최적화 한도를 **더 이상 소모하지 않음** → 어느 계정으로 배포하든 재발 방지.
- 브라우저가 Supabase CDN에서 직접 로드 (Storage는 이미 1년 CDN 캐시 적용됨).

## 5. 검증

- `npx tsc --noEmit` 통과.
- 수동 확인 방법:
  1. 배포본에서 `/usedgoods` 목록 페이지 진입 → 썸네일이 정상 렌더링되는지 확인.
  2. Network 탭에서 이미지 요청이 `/_next/image?...`가 아니라 **Supabase URL로 직접** 나가는지 확인.
  3. 콘솔에 402(`OPTIMIZED_IMAGE_REQUEST_PAYMENT_REQUIRED`)가 사라졌는지 확인.

## 6. 참고 / 남은 과제

- 향후 트래픽이 크게 늘어 Supabase egress가 부담되면, Vercel Pro 업그레이드(최적화 한도 확대) 또는 Supabase 자체 이미지 변환(`render/image`) 도입을 재검토.
- 현재는 업로드 시점 최적화로 원본이 충분히 작아 `unoptimized` 우회가 합리적인 선택.
