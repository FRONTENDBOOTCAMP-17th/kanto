# 이미지 402 에러 해결 — Vercel 이미지 최적화 전역 우회

- **날짜**: 2026-07-07
- **담당자**: 임태린
- **분류**: 핫픽스 / 이미지 렌더링 (Vercel 이미지 최적화 한도)
- **상태**: 완료
- **이슈**: #643
- **브랜치**: `hotfix/v1.3.3`

## 1. 배경 / 문제 정의

목록 페이지(`/usedgoods` 등)와 상세 페이지에서 이미지가 렌더링되지 않고 콘솔에 402 에러가 발생.

관찰된 응답 헤더:

| 항목 | 값 |
|------|-----|
| Status Code | `402 Payment Required` |
| `x-vercel-error` | `OPTIMIZED_IMAGE_REQUEST_PAYMENT_REQUIRED` |
| 요청 경로 | `/_next/image?url=https%3A%2F%2F...supabase.co...webp&w=1080&q=75` |

## 2. 원인

- Next.js `<Image>` 컴포넌트는 Vercel의 **Image Optimization**(`/_next/image`)을 통해 이미지를 리사이즈·변환해서 내려준다.
- Vercel 무료(Hobby) 플랜은 이 최적화 이미지 변환 개수에 **월 한도**가 있고, 초과하면 402를 반환한다.
- 목록 페이지는 한 번에 여러 장의 썸네일을 불러오므로 한도를 빠르게 소모한다. 상세/아바타 등 다른 곳도 동일하게 402가 발생.
- Supabase 원본 이미지 자체 문제가 아니라, **브라우저 → Vercel 최적화 → 원본** 경로의 중간(Vercel 최적화) 단계에서 막힌 것.

```
변경 전:  브라우저 → Vercel 최적화(여기서 402) → 원본(Supabase/카카오/구글 등)
변경 후:  브라우저 → 원본 (직접)
```

## 3. 조치 내용 (Vercel 최적화 전역 우회)

### `next.config.ts`

- `images.unoptimized: true` 추가.
- 모든 `next/image` 사용처(게시물 이미지, **아바타**, 정적 이미지 포함)가 Vercel 최적화(`/_next/image`)를 우회하고 원본 URL을 직접 로드한다.

```ts
images: {
  unoptimized: true,
  formats: ["image/avif", "image/webp"],
  minimumCacheTTL: 60 * 60 * 24 * 30,
  remotePatterns: [ ... ],
}
```

### 왜 전역 설정인가 (개별 컴포넌트 대신)

- 게시물 이미지는 공통 래퍼 `ImageWithFallback`를 거치지만, **아바타**는 여러 컴포넌트에서 `next/image`를 직접 사용한다
  (`RentSellerInfo`, `ChatHeader`, `PublicProfileCard`, `profileAvatar` 등).
- 컴포넌트마다 `unoptimized`를 붙이면 새 사용처가 생길 때마다 누락 위험이 있어, **전역 config 한 곳**으로 근본 해결한다.
- 초기에 `ImageWithFallback`에만 `unoptimized`를 적용했으나(PR #645), 전역 설정이 이를 완전히 대체하므로 래퍼의 중복 속성은 제거했다.

### 왜 화질/성능 손해가 거의 없는가

- Supabase 원본은 업로드 시점에 이미 **WebP + 긴 변 1600px 상한**으로 리사이즈되어 저장된다
  (참고: `docs/작업기록/20260703-supabase-이미지-트래픽-최적화.md`).
- 아바타는 카카오/구글 CDN 원본을 직접 받으며 크기가 작다.
- 정적 이미지(로고 등)도 작아 최적화 이득이 낮다.

## 4. 기대 효과

- 목록·상세·아바타·정적 이미지 등 **모든 이미지의 402 에러 제거**.
- Vercel 이미지 최적화 한도를 **더 이상 소모하지 않음** → 어느 계정으로 배포하든 재발 방지.
- 브라우저가 원본 CDN에서 직접 로드 (Supabase Storage는 1년 CDN 캐시 적용됨).

## 5. 검증

- `npx tsc --noEmit` 통과.
- 수동 확인 방법:
  1. 배포본에서 `/usedgoods` 목록 및 상세 페이지 진입 → 이미지·아바타가 정상 렌더링되는지 확인.
  2. Network 탭에서 이미지 요청이 `/_next/image?...`가 아니라 **원본 URL로 직접** 나가는지 확인.
  3. 콘솔에 402(`OPTIMIZED_IMAGE_REQUEST_PAYMENT_REQUIRED`)가 사라졌는지 확인.

## 6. 참고 / 남은 과제

- 향후 트래픽이 크게 늘어 Supabase egress가 부담되면, Vercel Pro 업그레이드(최적화 한도 확대) 또는 Supabase 자체 이미지 변환(`render/image`) 도입을 재검토.
- 현재는 업로드 시점 최적화로 원본이 충분히 작아 `unoptimized` 전역 우회가 합리적인 선택.
