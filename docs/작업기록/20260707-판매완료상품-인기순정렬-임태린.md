# 판매완료 상품이 인기순 정렬 상단에 노출되는 문제 수정

작성: `임태린`
일자: 2026-07-07
관련 이슈: #623

## 1. 배경

목록 페이지에서 "인기순" 정렬 시, 판매완료된 상품이 좌측 상단 "인기" 뱃지 없이도 목록 상단에 노출되는 문제가 발견됨.

## 2. 원인

- `recalculate_kpps()` 배치 함수(하루 2회, 03:30/15:30 pg_cron 실행)가 중고거래(`used_goods`)의 `kpps_score`를 재계산할 때 `is_sold=false`인 게시물만 대상으로 함(`supabase/migrations/20260623100000_kts_kpps_scoring.sql`).
- 판매완료 시점부터 해당 게시물의 `kpps_score`는 더 이상 갱신되지 않고, 판매 직전의 (높았던) 점수가 그대로 남는다.
- `is_popular` 뱃지 플래그는 매번 초기화 후 `is_sold=false`인 것 중 유형별 상위 5개에만 재부여되므로 정확히 꺼진다 → 뱃지는 정상적으로 안 뜸.
- 하지만 목록 정렬 쿼리(`src/services/usedGoods/usedGoods.ts`, `src/services/rental/rental.ts`의 `sort=popular` 분기)는 `is_sold`를 필터링하지 않고 이 얼어붙은 `kpps_score`로만 정렬 → 판매완료 상품이 뱃지 없이 상단에 남는다.
- 조사 중 렌탈 쪽 별개 버그도 발견: `is_popular` 부여 조건이 `(post_type != 'used_goods' OR is_sold = FALSE)`로 되어 있어, 렌탈 게시물에는 `is_sold` 체크가 아예 적용되지 않았음. 완료(판매/계약완료)된 렌탈도 인기 뱃지를 계속 받을 수 있었음.

## 3. 처리

### 3-1. 목록 정렬 쿼리 수정

`sort=popular` 분기에 `is_sold` 오름차순을 최우선 정렬 조건으로 추가. 판매완료 상품은 얼어붙은 `kpps_score`와 무관하게 항상 활성 상품보다 아래로 밀린다. 목록에서 사라지지 않고 순서만 뒤로 가는 점은 기존 다른 정렬 탭(판매완료 오버레이만 씌워 계속 노출)과 동일한 방식이다.

- `src/services/usedGoods/usedGoods.ts`
- `src/services/rental/rental.ts`

### 3-2. 렌탈 인기 플래그 게이트 수정

`recalculate_kpps()`의 `is_popular` 부여 조건에서 `post_type`과 무관하게 `is_sold = FALSE`가 적용되도록 통일. 배치 함수 재계산 로직(점수 산출 부분)은 변경하지 않고, `is_popular` 부여 UPDATE 문의 WHERE절만 수정.

- `supabase/migrations/20260707140000_fix_kpps_rental_sold_gate.sql` (신규, `CREATE OR REPLACE FUNCTION`으로 재정의, 끝에 `SELECT recalculate_kpps();` 호출로 기존 데이터에도 즉시 반영)

## 4. 변경 파일

| 파일 | 변경 내용 |
|---|---|
| `src/services/usedGoods/usedGoods.ts` | `sort=popular` 정렬에 `is_sold asc` 우선순위 추가 |
| `src/services/rental/rental.ts` | `sort=popular` 정렬에 `is_sold asc` 우선순위 추가 |
| `supabase/migrations/20260707140000_fix_kpps_rental_sold_gate.sql` | `recalculate_kpps()`의 `is_popular` 부여 조건에 렌탈도 `is_sold` 체크 적용 |

## 5. 결과

- "인기순" 정렬에서 판매완료 상품/렌탈이 얼어붙은 점수와 무관하게 항상 활성 게시물보다 아래로 배치된다.
- 완료된 렌탈이 다음 배치 실행 시 인기 뱃지를 잘못 유지하는 문제도 함께 해소된다.

## 6. 검증

- `npm run lint` 통과 확인 완료 (신규 경고/에러 없음).
- ⚠️ 이 세션에는 로컬 Docker(Supabase)가 실행되어 있지 않아 `supabase db reset` 및 실제 데이터 기반 정렬 결과 실측은 하지 못했다. 머지 전 아래 확인 필요:
  - 중고거래/렌탈 목록에서 "인기순" 선택 시, 판매완료 상품이 상단에 노출되지 않고 하단(오버레이 표시)으로 밀리는지 확인.
  - 로컬 Supabase 기동 후 마이그레이션 적용 → 판매/계약완료 처리된 렌탈 게시물의 `is_popular`가 `FALSE`로 바뀌는지 쿼리로 확인.
