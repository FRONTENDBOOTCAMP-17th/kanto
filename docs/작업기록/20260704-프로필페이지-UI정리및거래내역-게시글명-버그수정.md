# 프로필 페이지 UI 정리 + 거래 내역 게시글명 표시 버그 수정

작성: `DoHyck-Centric`
일자: 2026-07-04

## 1. 배경

프로필 페이지(`/profile`) UI를 다듬으면서, 거래 내역 탭에서 삭제된 게시글이
전부 "삭제된 게시글"로만 표시되는 문제를 함께 발견해 원인을 추적하고 고쳤다.

## 2. 프로필 페이지 UI 조정

- **바깥 배경 흰색 통일**: `page.tsx`의 페이지 전체 배경 `bg-white md:bg-teal-50`
  → `bg-white`. (처음엔 `ProfileCard.tsx` 자체의 배경/보더를 바꿨는데, 실제
  요청은 그 바깥을 감싸는 `page.tsx`의 배경이었어서 그쪽으로 다시 수정했다.)
- **아래쪽 섹션 바깥 보더 제거**: `ProfileCard.tsx`에서 사이드 메뉴 + 탭
  콘텐츠를 함께 감싸는 컨테이너의 `md:border md:border-gray-100` 삭제.
- **뒤로가기 아이콘 변경**: `ArrowLeft`(←) → `ChevronLeft`(<).
- **거래 내역에서 "결제 대기" 숨김**: `ProfileTransactionsSection.tsx`의
  `HIDDEN_STATUSES`에 `"pending"` 추가. 더 이상 쓰이지 않는
  `statusLabel.pending` 항목도 함께 제거.

## 3. 거래 내역 — 삭제된 게시글 제목이 안 보이는 버그

### 증상
게시글을 삭제하면 그 게시글이 얽힌 거래가 거래 내역 목록에서 실제 제목 대신
"삭제된 게시글"로 표시됨.

### 원인 조사
- 게시글 삭제는 소프트 삭제다: `status: "deleted"`로 UPDATE만 하고
  (`src/app/api/posts/[id]/route.ts`), 30일 뒤 cron이 실제 행을 지운다
  (`src/app/api/posts/cleanup/route.ts`).
- `posts` 테이블 자체는 존재하는데도 `null`이 나온 건, `getMyTransactions()`가
  RLS 적용받는 일반 클라이언트로 `posts(title)`를 조인했고, 삭제(비활성)된
  글은 조회 정책상 걸러졌기 때문.
- 여기서 한 단계 더 파고들어, "애초에 거래가 걸린 글은 30일 후에도 하드
  삭제가 되는가?"를 Supabase SQL Editor에서 직접 확인했다:
  ```sql
  select conname, conrelid::regclass, confdeltype
  from pg_constraint
  where contype = 'f' and confrelid = 'public.posts'::regclass;
  ```
  결과: `transactions_post_id_fkey`의 `on_delete`가 **NO ACTION**. 즉 거래가
  걸린 글은 cleanup 크론의 하드 삭제가 FK 위반으로 막혀 사실상 영구 보존되고
  있었다. (반면 `reviews_post_id_fkey`는 `SET NULL`이라, reviews 테이블은
  이미 `post_title` 컬럼에 제목을 스냅샷 저장해두는 방식으로 이 문제를
  회피하고 있었다.)

### 결정한 방향
"30일 후엔 실제로 하드 삭제되게 유지하고, 대신 거래 시점의 게시글명을
`transactions` 테이블에 직접 스냅샷 저장한다" — reviews 테이블이 쓰던 것과
동일한 패턴을 transactions에도 적용.

### 변경 내용
- **마이그레이션 추가** (`supabase/migrations/20260704000000_transactions_post_title_snapshot.sql`,
  아직 프로덕션 미적용 — Supabase SQL Editor에서 직접 실행 예정):
  - `transactions.post_title` 컬럼 추가 + 기존 데이터 백필
  - `post_id` 컬럼 nullable로 변경
  - `transactions_post_id_fkey`를 `NO ACTION` → `SET NULL`로 변경
- **거래 생성 시점에 제목 스냅샷**: `createPaymentRequestAction`
  (`paymentActions.ts`)에서 게시글 조회 시 `title`도 함께 select 해서
  `createTransaction`에 `postTitle`로 전달.
- **조회 단순화**: `getMyTransactions()`(`actions.ts`)는 더 이상 `posts`
  조인이나 관리자 클라이언트가 필요 없어져, `post_title` 컬럼만 그대로
  읽도록 정리. (중간에 임시로 관리자 클라이언트로 우회하는 수정을 했었는데,
  스냅샷 방식으로 가면서 필요 없어져 되돌렸다.)
- **후기 작성 흐름도 정리**: `createReviewAction`에서 별도로 `posts`를
  다시 조회하던 코드를 없애고 `transaction.post_title`을 그대로 재사용.
- `post_id`가 nullable로 바뀌면서 발생한 타입 에러 2건
  (`confirmReceiptAction`의 게시글 업데이트, 위 후기 작성 조회)을 null 가드로
  수정.
