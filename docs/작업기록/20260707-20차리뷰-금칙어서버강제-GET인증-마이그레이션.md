## 1. 배경

20차 리뷰 가이드의 [제안]/[사소] 3건을 처리했다. 발표 D-1 시점이라 급한 [필수]는 없었고, 가이드가 명시한 중요도 순서(1 → 2 → 3)대로 손봤다.

## 2. 처리

### 2-1. [제안] 금칙어 검사를 서버 insert 경로에서도 강제

**문제**: 중고·렌탈·구인 작성 폼이 브라우저에서 `/api/admin/profanity-rules/check` 를 호출해 금칙어를 막았는데, 이건 클라이언트 코드라 개발자 도구로 함수를 건너뛰거나 글 insert 를 직접 보내면 통과했다. 실제 차단 보장은 서버가 쥐어야 한다. 이미 도배 방지(rate limit)는 구인의 `createJobPostRecord` 서버 액션이 서버에서 강제하고 있어, 금칙어도 같은 결로 맞췄다.

**처리**:

1. **공용 판정 함수 추출** — `src/services/admin/adminContent.ts` 에 `containsProfanity(text, scope="post")` 추가. `check` 라우트가 이 함수를 쓰도록 리팩터해 로직을 한 군데로 모았다. 규칙 조회 실패 시 fail-open(통과)이며, 그 판단을 함수 주석으로 남겼다.
2. **글 등록을 서버 액션으로** — 중고·렌탈의 posts 레코드 생성을 서버 액션(`createUsedGoodsPostRecord`, `createRentalPostRecord`)으로 옮기고, 그 첫머리에서 `containsProfanity` 로 차단한다. 도배 방지(rate limit)도 이 액션 안으로 합쳐 구인 패턴과 통일했다(기존의 클라이언트 `/api/posts/rate-check` 호출 제거).
3. **구인** — 기존 `createJobPostRecord` 는 posts 생성·rate limit 을 이미 서버에서 처리하고 있어, 인자에 검사용 텍스트(`profanityText`)를 받아 `containsProfanity` 한 줄만 추가했다.

세 경로 모두, 위반 시 서버 액션이 `PROFANITY` 를 던지고 폼은 기존 Toast("부적절한 텍스트가 포함되었습니다")로 안내한다. 클라이언트 `/check` 호출은 빠른 안내용으로 그대로 뒀다(가이드 권고).

> 참고: 이미지 업로드와 상세 테이블(used_goods/rentals/jobs) insert 는 여전히 클라이언트에서 수행한다. 다만 부모인 posts 레코드가 서버 액션 없이는 만들어지지 않으므로, 금칙어가 있으면 글 자체가 생성되지 않는다.

### 2-2. [사소] 금칙어 규칙 목록 GET 에 인증

`src/app/api/admin/profanity-rules/route.ts` 의 `GET` 이 인증 없이 전체 금칙어 사전을 반환하고 있었다. 같은 파일 `POST` 가 쓰던 `getAdminUser()` 가드 한 줄을 `GET` 에도 붙였다. 이 목록 GET 은 관리자 화면(`ProfanityList.tsx`)만 호출하고, 사용자 경로는 모두 별도의 `/check`(boolean 만 반환, 그대로 개방)를 쓰는 것을 grep 으로 확인했다.

### 2-3. [제안] 마이그레이션 재현성

`public_profiles` 뷰(`security_invoker=on`)는 anon 조회 시 users 원본의 anon SELECT 정책을 따르는데, 그 RLS enable·anon SELECT 정책이 어느 마이그레이션에도 없고 Supabase 베이스라인에만 있었다(가이드 지적대로 grep 으로 확인). 백지 상태 `db reset` 시 뷰가 0행을 돌려줄 수 있다.

- `supabase/migrations/20260707000000_users_anon_public_select_policy.sql` 추가. `enable row level security`(멱등 no-op) + `drop policy if exists` 로 가드한 anon SELECT 정책(`deleted_at is null`)을 넣어 reset 재현성을 굳혔다.
- **⚠️ 미완료(팀 확인 필요)**: 이 세션엔 Docker(로컬 Supabase)가 없어 `supabase db reset` + anon 키 curl 실측을 하지 못했다. 머지 전 로컬에서 (1) `public_profiles` 이름 조회가 나오는지, (2) `users?select=email,phone` 이 `[]` 인지 실측할 것. 절차는 마이그레이션 파일 상단 주석에 적어 뒀다.
