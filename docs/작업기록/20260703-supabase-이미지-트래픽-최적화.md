# Supabase 이미지 트래픽 최적화 — 업로드 시점 WebP 변환 + 리사이즈

- **날짜**: 2026-07-03
- **담당자**: 김도혁
- **분류**: 성능 개선 / 백엔드(Storage) 비용 최적화
- **상태**: 완료 (배포 후 트래픽 추이 관찰 필요)

## 1. 배경 / 문제 정의

Supabase 트래픽(egress) 사용량이 플랜 한도에 근접할 정도로 과다하게 발생.
이미지가 트래픽의 대부분을 차지하는 구조였고, 원인을 분석한 결과 아래 4가지가 확인됨.

| # | 원인 | 상세 |
|---|------|------|
| 1 | **원본 이미지 그대로 업로드** | 중고거래·렌탈·구인·프로필·로고 등 모든 업로드 지점에서 폰 카메라 원본(수 MB jpg/png)을 리사이즈·압축 없이 Storage에 저장 |
| 2 | **lazy loading 무력화** | 공용 `ImageWithFallback` 컴포넌트에 `loading="eager"`가 하드코딩되어, 목록/캐러셀에서 화면 밖 이미지까지 전부 즉시 다운로드 |
| 3 | **CDN 캐시 기간 짧음** | Storage 업로드 시 `cacheControl` 미지정 → 기본 1시간. 캐시 만료마다 원본 재전송 |
| 4 | **일부 `<img>` 직접 사용** | next/image(Vercel 이미지 캐시)를 거치지 않고 Supabase 원본을 매번 요청하는 지점 존재 → 후속 과제로 분리 |

## 2. 조치 내용

### 2-1. 업로드 시점 이미지 최적화 유틸 신설 — `src/utils/optimizeImage.ts`

- 브라우저 canvas 기반으로 **비율 유지 + 긴 변 상한 축소**(확대 없음) 후 **WebP(품질 0.8)** 변환
- WebP 인코딩 미지원 브라우저(구형 Safari)는 JPEG 폴백
- 변환 결과가 원본보다 크거나 변환 실패 시 원본 유지, GIF/SVG는 대상 제외

### 2-2. 적용 지점 (상한 크기)

| 지점 | 파일 | 상한 |
|------|------|:---:|
| 게시물 이미지 공용 훅 (구인·중고) | `src/hooks/useImageUpload.ts` — 선택 시점(모더레이션 통과 직후) 압축 | 1600px |
| 중고거래 작성/수정 폼 (선택·드롭) | `src/app/(user)/usedgoods/create/_components/CreateUsedGoodsForm.tsx` | 1600px |
| 렌탈 작성/수정 폼 (선택·드롭) | `src/app/(user)/rental/create/_components/RentalCreateForm.tsx` | 1600px |
| 프로필 아바타 | `src/services/profile/profileInfo.ts` — `uploadAvatar` | 512px |
| 회사 로고 | `src/hooks/useCreateJobForm.ts` — `uploadLogo` | 512px |

- 선택 시점에 압축하므로 **미리보기도 실제 업로드본과 동일**
- 아바타는 `avatars/{userId}/profile` 고정 경로(확장자 없음)라 파일명에 `.webp`가 안 보이지만 contentType은 `image/webp`로 저장됨

### 2-3. CDN 캐시 기간 연장

- 타임스탬프 기반 **고유 경로** 업로드에 `cacheControl: "31536000"`(1년) 지정
  - 적용: 게시물 이미지 전체 (`useCreateJobForm`, `useCreateUsedGoodsForm`, `CreateUsedGoodsForm`, `RentalCreateForm`)
  - 미적용(기본 1시간 유지): 아바타·로고 — 고정 경로 + upsert라 stale 캐시 위험이 있어 제외

### 2-4. lazy loading 복원 — `src/components/common/ImageWithFallback.tsx`

- `loading="eager"` 제거 → next/image 기본 lazy loading 복원
- 목록/캐러셀 이미지가 뷰포트에 들어올 때만 로드됨
- 첫 화면 LCP 이미지가 느려지는 곳이 생기면 해당 사용처에만 `priority` 지정으로 대응

### 2-5. 기존 저장분 처리

- Storage에 이미 있던 jpg/png는 **수동으로 WebP 전환 완료** (본 작업 이전에 수행)
- 일괄 변환 스크립트(`scripts/convert-storage-to-webp.ts`)는 역할이 끝나 삭제함

## 3. 기대 효과

- **저장 용량·업로드 트래픽**: 원본 수 MB → 리사이즈+WebP 후 통상 수백 KB 이하 (약 70~90% 절감)
- **다운로드 트래픽(egress)**: 파일 자체 축소 × lazy loading으로 요청 수 감소 × CDN 1년 캐시의 복합 효과
- 신규 업로드는 전부 `.webp`로 저장되므로 비-WebP 파일이 다시 쌓이지 않음

## 4. 검증

- `npx tsc --noEmit` 통과, 변경 파일 ESLint 통과
- 수동 확인 방법:
  1. `npm run dev` → 중고/렌탈 글쓰기에서 큰 사진(3~5MB) 업로드
  2. Supabase 대시보드 → Storage에서 해당 파일이 `.webp`, 수백 KB 이하인지 확인
  3. 프로필 사진 변경 후 `avatars/{userId}/profile`의 metadata mimetype이 `image/webp`인지 확인
  4. 목록 페이지에서 Network 탭 열고 스크롤 → 이미지가 스크롤 시점에 로드되는지 확인
- 배포 후 Supabase 대시보드의 **Egress 그래프 추이**로 최종 효과 확인
