# 칸토Go 공유 URL "참여" 버튼 "처리 중..." 멈춤 버그 수정 + 드로어 공유 버튼 추가

- 작성일: 2026-07-06
- 관련 파일:
  - `src/components/go/MeetupDetailPanel.tsx`
  - `messages/ko.json`, `messages/en.json`, `messages/fil.json`

## 1. 증상

배포된 칸토Go에서 모임을 클릭하면 URL이 `/go?m=<암호화 토큰>` 으로 바뀐다.
이 링크를 다른 사람에게 공유해 열면, 우측 드로어(`MeetupDetailPanel`)의 **"참여" 버튼이
"처리 중..."에서 영구히 멈추고** 클릭이 불가능한 상태가 되는 버그가 있었다.

## 2. 근본 원인

"처리 중..." 버튼은 클릭 후 로딩이 아니라 **클릭 전 "내 참여 상태" 조회 게이트**다.
`MeetupDetailPanel.tsx`의 파생값 `statusLoading` 은 다음과 같다.

```tsx
const statusLoading = currentUserId
  ? myStatusState.postId !== meetup.post_id ||
    myStatusState.userId !== currentUserId ||
    myStatusState.status === "loading"
  : false;
```

이 플래그는 **오직 `getMyMeetupStatus` 응답이 도착해
`myStatusState.userId === currentUserId` 가 될 때만 풀린다. 타임아웃·폴백·재시도가 없었다.**

### 공유 URL 콜드 로드에서만 터지는 흐름

1. `/go` 는 서버 컴포넌트지만 `?m` 쿼리를 서버에서 사용하지 않아 일반 맵만 렌더한다.
   패널은 클라이언트에서 `getMeetupByToken(token)` 서버 액션이 끝난 뒤에야 열린다
   (`GoClient.tsx` 의 최초 마운트 effect). **앱 내에서 핀/목록을 클릭하는 경로엔 이 서버 액션이 없다.**
2. 로그인 세션(`currentUserId`)은 Zustand 스토어에 **비동기로** 채워진다.
   콜드 로드에서는 `undefined → 숫자` 로 뒤늦게 바뀐다.
3. 이 전환이 `statusLoading` 을 `true` 로 밀어올린다(마운트 시 캡처된 `userId` 가 `null` 이라
   새 `currentUserId` 와 불일치). 곧바로 `getMyMeetupStatus` 재조회가 걸린다.
4. 이 조회가 realtime 이 반복 호출하는 `getActiveMeetups` + `getMeetupByToken` 등
   다른 서버 액션과 **큐에서 경합·지연**되면, 그 사이 버튼은 "처리 중..."에 갇히고
   **복구 수단이 전혀 없다.**

즉 구조적 원인은 **"클릭 전 상태 조회 한 번에 버튼 전체를 걸어두고, 그게 안 오면 영구 정지"** 였다.
공유 URL 경로가 이 조회를 가장 심하게 지연시켜 버그가 이 경로에서만 두드러졌다.

## 3. 수정 1 — 상태 조회 타임아웃/폴백

`statusLoading` 이 절대 영구 정지하지 않도록, 상태 조회 effect에 **타임아웃 폴백(4초)** 을 추가했다.
4초 내 실제 상태가 안 오면 `myStatusState` 를 `status: "none"`(미참여)로 확정해 게이트를 풀고
"참여하기" 버튼을 노출한다. 실제 응답이 나중에 도착하면 그 정확한 값으로 정정한다.

```tsx
if (currentUserId) {
  let resolved = false;
  const applyStatus = (status: MyMeetupStatus) => {
    resolved = true;
    if (active) {
      setMyStatusState({ postId: meetup.post_id, userId: currentUserId, status });
    }
  };
  getMyMeetupStatus(meetup.post_id).then(applyStatus).catch(() => applyStatus("none"));

  statusFallback = setTimeout(() => {
    if (active && !resolved) {
      setMyStatusState({ postId: meetup.post_id, userId: currentUserId, status: "none" });
    }
  }, 4000);
  // ...
}
// cleanup: clearTimeout(statusFallback)
```

**안전성**

- 폴백이 "none"으로 풀린 뒤 사용자가 참여 클릭 시 — 실제로 이미 참여 중이면
  `joinMeetup` 이 `existing.status === "joined"` → 조용히 `return`(`go.ts`)하므로 중복 참여가 없다.
- 취소 이력이 있으면 기존대로 `REENTRY_FORBIDDEN` 토스트로 정상 안내된다.
- 로그아웃 상태에서는 `statusLoading` 이 원래부터 `false` 라 "처리 중"이 뜨지 않는다.
  폴백은 로그인 경로에만 적용되므로 부작용이 없다.

## 4. 수정 2 — 드로어에 "공유" 버튼 추가

URL을 수동 복사하지 않고도 공유할 수 있도록, 드로어 헤더의 신고 버튼 **왼쪽에 공유 버튼**을 추가했다.
(호스트 포함 항상 노출)

- 아이콘: lucide-react `Share2`
- 핸들러 `handleShare`: `meetup.id_token` 으로 `${origin}/go?m=<토큰>` 링크를 구성해
  클립보드에 복사하고, 기존 `showToast` 로 "URL이 복사되었습니다." 토스트를 띄운다.
  (`id_token` 이 없으면 `window.location.href` 로 폴백 — 이미 `?m=토큰` 이 들어있음)

```tsx
const handleShare = async () => {
  const shareUrl = meetup.id_token
    ? `${window.location.origin}/go?m=${meetup.id_token}`
    : window.location.href;
  try {
    await navigator.clipboard.writeText(shareUrl);
    showToast(t("toast.urlCopied"));
  } catch {
    showToast(t("toast.error"), true);
  }
};
```

동일 패턴이 `src/components/common/InteractionButtons.tsx` 에 이미 존재하나,
드로어의 기존 코드 스타일(인라인 핸들러 + `showToast` 재사용)에 맞춰 유틸 추출 없이 인라인으로 구현했다.

## 6. 검증

1. `/go` 에서 모임 클릭 → URL이 `/go?m=<토큰>` 으로 바뀌는지 확인.
2. **버그 수정**: 그 URL을 다른 브라우저/시크릿에서 로그인·로그아웃 각각으로 새로 열어,
   참여 버튼이 "처리 중..."에 갇히지 않고 늦어도 ~4초 내 "참여하기"/"참여 취소"로 확정되는지 확인.
   실제 참여 중인 계정으로 열어 "참여 취소"가 뜨는지(또는 폴백 후 참여 클릭이 중복 없이 처리되는지) 확인.
3. **공유 버튼**: 드로어 헤더의 공유 버튼 클릭 → "URL이 복사되었습니다." 토스트,
   클립보드에 `/go?m=<토큰>` 링크 복사, 붙여넣어 연 링크가 해당 모임 패널을 정확히 여는지 확인.
4. `npm run lint` — 변경 파일은 lint 클린.
   (`MeetupDetailPanel.tsx` 의 `react-hooks/set-state-in-effect` 경고는 이번 작업과 무관한
   기존 `setRenderMeetup` effect 의 것으로, 본 작업에서 건드리지 않음.)
