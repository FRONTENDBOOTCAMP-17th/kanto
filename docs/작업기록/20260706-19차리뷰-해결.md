## 1. [필수] anon `users` 보안 수정의 마이그레이션화

**파일:** `supabase/migrations/20260706000000_public_profiles_and_lock_users.sql` (신규)

**문제:** 라이브 DB 는 anon 이 `users` 를 못 읽는 안전한 상태지만, 그 상태를 만든 변경이 운영 DB 에만 손으로 적용됐고 저장소 마이그레이션엔 없다.
- `20260626000000_grant_anon_select_users.sql` 은 지금도 `grant select on public.users to anon;` 을 실행 → RLS 는 행만 걸러 email·phone 같은 컬럼이 통째로 열리는 구멍.
- 서비스 전반이 쓰는 `public_profiles` 뷰 정의가 어느 마이그레이션에도 없음(`grep -rn public_profiles supabase/migrations/` → 0건). 새 환경 `db reset` 시 목록·상세·채팅·GO 쿼리가 전부 깨짐.

**처리:** 새 마이그레이션에서
1. `public_profiles` 뷰를 `security_invoker=on` 으로 정의(공개 안전 컬럼 `id, name, avatar_url, auth_id, created_at, deleted_at` 만 — `src/type/supabase.ts` 의 뷰 타입과 일치).
2. anon 의 통짜 `users` SELECT 를 회수하고, 뷰가 필요로 하는 안전한 컬럼만 **컬럼 단위 GRANT** 로 재허용(RLS 행 필터 + 컬럼 GRANT 조합으로 "anon 은 비삭제 행의 공개 컬럼만").

**⚠️ 남은 검증(중요):**
- 이 마이그레이션은 리뷰 가이드 템플릿 + 타입 정의 기준으로 작성했고, **이 세션에서는 운영 DB 접근 인증이 없어 라이브 상태와 실측 대조를 하지 못했다.** 적용 전 반드시 Supabase SQL 에디터에서 실제 뷰 정의·GRANT·RLS 를 대조하고, 적용 후 anon 키로 `GET /rest/v1/users?select=email,phone` 이 PII 를 안 내려주는지 실측할 것. (SQL 은 마이그레이션 파일 주석과 리뷰 가이드에 있음)
- **추가 발견:** `public_user_profiles` 뷰(avg_rating·like_count·post_count·role 포함, `src/services/user/publicProfile.ts` 사용)도 마이그레이션에 정의가 없다. 리뷰가 명시한 범위(`public_profiles`)는 아니지만 같은 재현성 구멍이므로, 라이브 정의를 확보해 후속으로 함께 굳히는 것을 권장한다.
- 근본적으로 `users`/`posts`/`chats` 등 핵심 테이블의 최초 `CREATE TABLE` 자체가 마이그레이션에 없어(23차 리뷰에서도 지적), 완전한 `db reset` 재현성은 별도 과제다.

## 2. [사소] 목록 정렬 경로별 필터 규칙 통일

**파일:** `src/services/job/job.ts`

정렬에 따라 부모(`posts`) 기준과 자식(`jobs`) 기준으로 뒤집어 조회하는데, 같은 필터라도 컬럼 접두사가 갈렸다(`jobs.employee_type` ↔ `employee_type`, `posts.title` ↔ `title` 등). 한쪽만 고치면 정렬에 따라 결과가 달라지는 실수 위험.

- 경로별 컬럼 이름을 `POSTS_BASED_COLUMNS` / `JOBS_BASED_COLUMNS` 한 곳에 모으고, 스칼라 필터(userId·검색·고용형태·급여형태·지역) 적용을 공통 헬퍼 `applyScalarFilters` 로 통일.
- `targetIds` 는 빈 배열일 때 "결과 없음" 으로 조기 반환하는 제어 흐름이 있어 호출부에 남김(컬럼명만 경로별로 유지).
- 미사용이 된 `TradeLocation` import 제거.

## 4. [제안] `lockScroll` 동시 잠금 시 조기 해제

**파일:** `src/utils/lockScroll.ts` 외 4개 호출부

여러 컴포넌트가 동시에 스크롤을 잠글 때(모달 위 셀렉트 등) 먼저 닫히는 쪽이 잠금을 풀면 뒤에 남은 쪽의 스크롤이 되살아나던 문제.

- `lockScroll`/`unlockScroll` 을 **참조 카운트**로 변경: 첫 잠금에서만 스타일을 걸고, 마지막 잠금이 풀릴 때만 해제.
- 단순 카운터가 정확하려면 모든 호출자가 lock 1회당 unlock 1회로 균형을 이뤄야 하는데, `cond ? lockScroll() : unlockScroll()` 패턴(짝 없는 unlock)이 4곳 있었다. 이들을 `if (!open) return; lockScroll(); return () => unlockScroll();` 로 바꿔 균형화.
  - `MainSearchBar.tsx`, `AgreeSection.tsx`, `FilterDropdown.tsx`, `responsive-select.tsx`
- 나머지 호출부(모달류 7곳)는 이미 균형 호출이라 변경 없음.

## 5. [사소] `Header` `initialNotices` 필수 prop화 — 확인 결과 조치 불필요

리뷰는 "옵셔널(`?`)이면 필수로 바꾸라"는 제안이었으나, 확인해보니 `Header`·`GoNoticeIcon`·`UnifiedBanner`·`GlobalLayout` 모두 이미 `initialNotices` 를 **필수 타입**으로 받고 있다(옵셔널 아님). 이번 리뷰 델타의 `fix: GlobalLayout에서 Header에 initialNotices prop 누락 수정` 커밋으로 이미 닫힌 상태라, 불필요한 변경 대신 확인만 기록한다.
