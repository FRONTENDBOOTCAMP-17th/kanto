# 이미지 렌더링 지연 해결

작성: `이동근`
일자: 2026-07-06
근거 커밋: `3b38b46`

## 1. 배경

목록 카드와 렌탈 상세 이미지 캐러셀에서 다음 이미지로 이동할 때 이미지가 늦게 나타나는 문제가 있었다. 사용자는 버튼 클릭 또는 스와이프 직후 빈 영역이나 로딩 지연처럼 느껴지는 화면을 보게 된다.

## 2. 원인

- 현재 보이는 이미지만 적극적으로 로드되고, 이전/다음 이미지는 전환 시점에야 로드되는 구조였다.
- `ContentCard`의 캐러셀은 hover/touch 전까지 인접 이미지를 준비하지 않았다.
- `ImageWithFallback`은 최초 `src`가 실패하면 내부 state를 fallback 이미지로 바꾸는데, 이후 `src` prop이 바뀌어도 fallback 상태가 남을 수 있었다.

## 3. 처리

### 3-1. 렌탈 상세 캐러셀 인접 이미지 선로딩

`ImageCarousel`에서 현재 인덱스를 기준으로 이전/다음 이미지 인덱스를 계산했다.

- 이미지가 1개 이하이면 선로딩 없음
- 이전/다음 인덱스가 같아질 수 있는 2장 케이스는 `Set`으로 중복 제거
- 인접 이미지는 `invisible`, `aria-hidden`, `loading="eager"`로 렌더링해 레이아웃에는 영향을 주지 않고 브라우저 캐시만 준비
- 이전 이미지와 현재 이미지도 전환 시 지연을 줄이기 위해 eager 로드 적용

### 3-2. 목록 카드 캐러셀 인접 이미지 warming

`ContentCard`에서는 모든 카드의 인접 이미지를 즉시 eager 로드하면 목록 성능에 부담이 될 수 있어, 조건부로 warming을 걸었다.

- `priority` 카드 또는 사용자 상호작용이 있는 카드만 인접 이미지 선로딩
- `onMouseEnter`, `onFocus`, `onTouchStart`에서 `shouldPreloadAdjacent` 활성화
- 터치 스와이프 시작 시 기존 drag handler를 유지하면서 선로딩도 함께 수행

### 3-3. fallback 이미지 상태 수정

`ImageWithFallback`은 `failedSrc`를 따로 저장하도록 변경했다.

- 현재 `src`와 실패한 `src`가 같을 때만 fallback 이미지 사용
- 이후 다른 `src`가 들어오면 정상적으로 새 이미지를 다시 시도

## 4. 변경 파일

| 파일 | 변경 내용 |
|---|---|
| `src/app/(user)/rental/[id]/_components/ImageCarresel.tsx` | 이전/다음 이미지 eager 선로딩 |
| `src/components/common/ContentCard.tsx` | hover/focus/touch 기반 인접 이미지 warming |
| `src/components/common/ImageWithFallback.tsx` | fallback state를 현재 src 기준으로 동작하게 수정 |

## 5. 결과

- 캐러셀 이동 직후 이미지가 늦게 뜨는 체감 지연을 줄였다.
- 목록 전체 이미지 트래픽을 한 번에 늘리지 않고, 우선순위 카드와 상호작용한 카드 중심으로만 선로딩한다.
- 실패 이미지 fallback 이후 다른 이미지로 바뀔 때도 정상 로드를 다시 시도한다.

## 6. 검증

- 렌탈 상세 이미지 캐러셀에서 이전/다음 이동 시 빈 화면이 보이지 않는지 확인 필요
- 목록 카드 hover, 키보드 focus, 모바일 swipe에서 다음 이미지 전환이 즉시 반응하는지 확인 필요
- 깨진 이미지 URL 이후 정상 URL로 바뀌는 경우 fallback이 고정되지 않는지 확인 필요
