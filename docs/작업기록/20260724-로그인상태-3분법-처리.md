# 로그인 상태 3분법 처리 — 인증 확인 전/로그인/비로그인 구분

- **날짜**: 2026-07-24
- 관련 작업: [세션유저-프리페치-제거](20260724-세션유저-프리페치-제거.md)의 후속 수정 (코드 리뷰 지적 반영)

---

## 배경 — 문제 발견

[세션유저-프리페치-제거](20260724-세션유저-프리페치-제거.md) 작업에서 루트 레이아웃의 서버 사이드 세션 유저 프리페치(`getSessionUser()`)를 제거하면서, 로그인 여부 판단을 전적으로 클라이언트(`useAuthInit`)에 맡기게 됨. 이 상태에서 코드 리뷰를 통해 다음 지적을 받음:

> 현재는 Zustand의 `user: null`이 '인증 확인 전'과 '비로그인'을 동시에 의미해, 기존 로그인 사용자에게 로그인 버튼이 먼저 노출될 수 있다.

확인 결과 정확한 지적이었음. `src/store/authStore.ts`의 `user` 필드는 애초에 "로그인된 유저 정보 or null"이라는 이분법으로 설계되어 있었고, `Header.tsx`는 `user ? <프로필메뉴> : <로그인버튼>` 형태로 렌더링하고 있었음. 그 결과:

- 서버 프리페치가 있던 이전에는 `initialUser`가 즉시 채워져 있어 문제가 없었음.
- 프리페치 제거 후에는 `useAuthInit`이 `onAuthStateChange`로 세션을 확인하는 그 짧은 시간 동안 `user`가 `null`이고, 이게 "확인 중"인지 "정말 로그아웃"인지 구분이 안 되어 **원래 로그인해 있던 유저에게도 로그인 버튼이 먼저 보이는** 문제가 발생.

---

## 무엇을 수정했나

| 파일 | 변경 내용 |
|---|---|
| `src/store/authStore.ts` | `status: "initializing" \| "authenticated" \| "unauthenticated"` 필드 추가. 초기값 `"initializing"`. `setUser()`는 `status: "authenticated"`로, `clearUser()`는 `status: "unauthenticated"`로 전이시킴. |
| `src/hooks/useAuthInit.ts` | `onAuthStateChange` 콜백에서 세션이 없는 경우(`if (!session) return;`)를 `clearUser()` 호출 후 `return`으로 변경. (아래 "함께 고친 부분" 참고) |
| `src/components/common/Header.tsx` | `authStatus` 구독 추가. 데스크톱 프로필/로그인 영역과 모바일 메뉴의 로그인 영역, 두 곳에서 `authStatus === "initializing"`일 때 로그인 버튼 대신 중립 스켈레톤(`animate-pulse` 회색 placeholder)을 렌더링하도록 분기 추가. |

## 함께 고친 부분 (상태 추가로 드러난 잠재 문제)

`useAuthInit.ts`에서 세션이 없을 때(`if (!session) return;`) 아무 상태 변경 없이 그냥 리턴하는 코드가 있었음. 기존 이분법(`user: null`)에서는 문제가 안 됐지만(`user`는 원래도 `null`), 3분법을 도입하면 이 분기를 그대로 두면 **정말로 로그아웃한 방문자도 `status`가 영원히 `"initializing"`에 머무르게 되어 placeholder가 계속 떠 있는** 새로운 버그가 생김. 그래서 이 분기에도 `clearUser()`를 호출해 `status`가 `"unauthenticated"`로 확실히 전이되도록 같이 수정함.

## 왜 이렇게 수정했나

- 상태를 3분법으로 나누는 것 자체가 리뷰어의 제안이자 표준적인 해법 — "모른다"와 "아니다"를 같은 값(`null`)으로 표현하면 항상 이런 종류의 오탐(false negative) 버그가 생김.
- placeholder는 기존 로그인 버튼/아바타와 크기를 맞춘 단순 회색 스켈레톤으로 처리 — 레이아웃 시프트 없이 "지금은 모름"을 시각적으로 표현.
- `FloatingChatWidget.tsx`는 이번에 손대지 않음: 이 컴포넌트는 `isLoggedIn`이 거짓이면 아예 `return null`(위젯 자체를 숨김)이라, 로그인 여부를 확인하는 동안에도 "숨김" 상태일 뿐 잘못된 정보를 보여주는 게 아니라서 이번 버그와 성격이 다르다고 판단.

---

## 긍정적 효과

- 원래 로그인해 있던 유저에게 로그인 버튼이 잘못 노출되는 문제 해결 — 인증 확인 전에는 중립 placeholder만 보임.
- `status` 필드가 생기면서 앞으로 다른 컴포넌트에서도 "확인 중"과 "로그아웃"을 구분해서 쓸 수 있는 기반이 마련됨.

## 부정적 효과 / 트레이드오프

- 로그인 버튼이 즉시 안 보이고 아주 짧게 회색 스켈레톤이 보이는 지점은 여전히 남음 — 다만 이건 "틀린 정보(로그인 버튼)"가 아니라 "정직하게 모른다고 표시"하는 것이라 이전과 성격이 다름.
- **이번 수정은 Vercel 비용 절감과 무관함**: `getSessionUser()` 제거로 인한 UX 부작용을 보완하는 수정일 뿐, 캐싱 여부 자체는 여전히 [세션유저-프리페치-제거](20260724-세션유저-프리페치-제거.md) 문서에 정리된 i18n 로케일 감지 문제에 막혀 있음. 즉 비용 절감 효과는 이 수정과 별개로 아직 미실현 상태.

## 검증

- `npx tsc --noEmit -p tsconfig.json` — 변경한 3개 파일 포함 소스 코드 오류 0건.
- 기존 `useAuthStore` 사용처(20여 개 파일) 전수 확인 — 모두 `{ user }`, `{ isLoggedIn }`, `{ setUser, clearUser }` 등 구조분해 방식이라 `status` 필드 추가로 인한 타입 충돌 없음.
- **브라우저 실사용 테스트는 아직 미실시** — 로그인된 상태에서 새로고침 시 실제로 깜빡임 없이(또는 짧은 스켈레톤만) 프로필이 뜨는지 확인 필요.

## 후속 (미처리)

- 브라우저에서 실제 로그인 유저로 새로고침해 placeholder → 프로필 전환이 자연스러운지 확인.
- i18n 로케일 감지(`src/i18n/request.ts`) 수정은 여전히 별도 작업으로 보류 상태 — [세션유저-프리페치-제거](20260724-세션유저-프리페치-제거.md) 문서 참고. 이게 해결돼야 Vercel 비용 절감 효과가 실제로 나타남.
