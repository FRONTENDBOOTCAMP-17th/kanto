# 공지 배너 UI/UX 개선 — press 애니메이션 복원, 헤더 아이콘 전환, SSR 선로딩

작성: `DoHyck-Centric`
일자: 2026-07-05
브랜치: `fix/557-uiux-animation`

## 1. 배경

모바일 공지 배너(매달림 탭) 관련 UI/UX 불편 3가지를 개선했다.

1. 탭을 눌러도 "아래로 눌리는" 애니메이션이 보이지 않음
2. 목록/상세/알림 페이지에서 매달림 탭이 콘텐츠를 가림 → 칸토Go처럼 헤더
   아이콘으로 노출하고 싶음
3. 새로고침 시 헤더의 다른 요소들이 먼저 그려진 뒤 공지가 뒤늦게 나타남

## 2. 공지 탭 press 애니메이션 복원

### 증상
`UnifiedBanner.tsx`의 모바일 공지/제재 탭에 `active:translate-y-1.5`(누르면
6px 내려감)가 있는데도 실제로는 보이지 않음.

### 원인
`globals.css`의 전역 규칙이 모든 버튼/링크에 press 시 확대 효과를 적용:

```css
button:not(:disabled), a {
  @apply transition-transform duration-100 active:scale-[1.05];
}
```

확대 효과가 함께 걸리면서 미세한 translate가 시각적으로 묻혔다.

### 수정
두 탭 버튼에 `active:scale-100`을 추가해 전역 scale을 상쇄
(`.dropdown-item`이 이미 쓰던 패턴과 동일).

## 3. 목록·상세·알림 페이지에서 헤더 아이콘으로 전환

- `UnifiedBanner.tsx`에 `noticeShownInHeader(pathname)` 헬퍼 추가:
  `/usedgoods`, `/job`, `/rental`, `/notifications` prefix 매칭.
- 해당 경로에서는 모바일 매달림 **공지 탭을 렌더링하지 않고**, 대신
  `Header.tsx`에서 칸토Go가 쓰던 `GoNoticeIcon`(확성기 아이콘 + 공지 모달)을
  헤더에 표시.
- 데스크탑은 기존 공지 배너 띠가 그대로 있으므로 헤더 아이콘은
  `md:hidden`으로 모바일 전용 제한 (`/go`는 기존처럼 항상 표시).
- prefix 매칭이므로 `/usedgoods/create`, `/rental/[id]/edit` 같은 작성/수정
  페이지에도 헤더 아이콘 방식이 적용됨 (의도된 트레이드오프).
- 제재 안내(빨간 탭)는 요청 범위 밖이라 기존 매달림 탭 유지.

## 4. 새로고침 시 공지가 뒤늦게 등장하는 문제 (SSR 선로딩)

### 원인
`UnifiedBanner`/`GoNoticeIcon`이 클라이언트 마운트 후
`fetch("/api/admin/notices")`로 데이터를 가져오는 구조라, 헤더의 다른
아이콘들이 먼저 그려진 뒤 API 응답이 오면 공지가 나타나 레이아웃이 튀었다.

### 수정 — `initialUser`와 동일한 서버 선로딩 패턴
- `adminNotices.ts`에 `getActivePublicNotices(locale)` 추가: 활성 공지만
  로케일에 맞는 제목으로 반환. 조회 실패 시 빈 배열 (페이지 렌더링 보호).
- `app/layout.tsx`(서버)에서 `getSessionUser`, `getMessages`와 `Promise.all`로
  병렬 fetch 후 `initialNotices`로 전달.
- prop 체인: `RootLayout → GlobalLayout → Header → UnifiedBanner / GoNoticeIcon`.
- 두 컴포넌트의 notices state를 `useState(initialNotices)`로 초기화 →
  SSR HTML부터 공지 아이콘/배너가 포함됨. 기존 클라이언트 fetch는 로케일
  변경 대응 겸 최신화 용도로 유지.

### 함께 처리한 hydration 이슈
"오늘 하루 보지 않기"는 `localStorage` 저장이라 서버가 읽을 수 없다.
렌더 중 직접 읽던 `isHiddenToday()`를 그대로 두면 SSR HTML과 클라이언트 첫
렌더가 달라져 hydration 불일치가 발생한다.

- `isHiddenToday()` → `getHiddenIds()`로 바꾸고, 렌더에서는 `hiddenIds`
  state(초기값 `[]`)로만 필터링.
- `hiddenIds` 로드는 기존 fetch effect의 `.finally()`에서 수행.
  (마운트 effect에서 동기 `setState`를 하면 `react-hooks/set-state-in-effect`
  lint 에러 — `NoticeBadge`가 쓰던 fetch 콜백 패턴을 따름.)
- 트레이드오프: "오늘 하루 보지 않기"를 체크했던 사용자는 새로고침 직후
  공지가 잠깐 보였다가 사라질 수 있음 (fetch 완료까지). 실사용상 허용 가능한
  수준으로 판단.
