# 목록 페이지 필터 모달 통합 설계 (2026-07-04)

## 왜 하는 작업인가

구인구직(`/job`) / 렌탈(`/rental`) / 중고거래(`/usedgoods`) 세 목록 페이지가 각자 다른 규칙으로 필터 칩을 나열하고 있다.

- 구인구직: 근무형태 칩 1개만 있음.
- 렌탈: 거래형태(매매/월세) 칩이 **정렬이 가격순일 때만** 나타나고, 다른 정렬에서는 숨겨지면서 필터 자체도 무시됨(`page.tsx`의 `isPriceSort` 결합).
- 중고거래: 카테고리 칩 1개만 있음.
- 세 페이지 모두 검색바 안에 지역 드롭다운이 별도로 존재해서, "검색"과 "필터"가 한 화면에 분산되어 있음.

이걸 하나의 UX로 통일한다: **"필터" 버튼 → 모달에서 카테고리별 항목 선택 → "필터 적용" 버튼으로 한 번에 커밋**. 적용된 필터는 필터 버튼 옆에 칩으로 나타나고, 칩의 X를 누르면 그 필터만 즉시 해제된다. 지역 선택도 검색바에서 모달 안으로 옮긴다.

이미 관련 리팩터링이 브랜치(`design/listpage-ui-improvement`)에 일부 진행 중이다 (`FilterChips.tsx`/`SortSelect.tsx`/`ListPageHero.tsx` 신규 추가, `PopularJobs.tsx` 삭제 등 미커밋 상태). 이 작업은 그 위에 이어서 진행한다.

## 확정된 요구사항 (제품 결정 사항)

- **필터 범위 확장** — 각 상세페이지 내용 기준으로 구매자가 걸 만한 항목까지 넓힌다.
  - Job: 지역, 근무형태(`employee_type`), 급여형태(`salary_type`)
  - Rental: 지역, 세부지역(barangay), 방구조(`room_type`), 거래형태(`rent_type`)
  - UsedGoods: 지역, 세부지역(barangay), 카테고리(`category`), 상품상태(`condition`)
- **항목당 단일 선택** (다중 선택 아님). 기존 `.eq()` 쿼리, URL 파라미터 1개 = 값 1개 구조를 그대로 유지한다.
- **지역 드롭다운은 모달로 이동.** 검색바는 텍스트 검색 전용이 된다.
- **적용된 필터 칩은 X 클릭으로 개별 즉시 해제.**

## 지금 상태 (구현 전 사실관계)

전부 URL `searchParams` 기반이다. `page.tsx`(서버 컴포넌트)가 `searchParams`를 읽어서 서비스 함수에 넘기고, 결과를 렌더링한다. 필터를 바꾸는 모든 클라이언트 동작은 `src/hooks/useUrlParams.ts`의 `updateParams(updates)`를 통한다:

```ts
// src/hooks/useUrlParams.ts
const { updateParams } = useUrlParams();
updateParams({ location: "Makati", type: "all" });
// - 여러 key를 한 번에 반영 가능 (모달의 "필터 적용" 배치 커밋에 그대로 맞음)
// - 값이 falsy 이거나 "all" 이면 해당 파라미터 삭제 ("all" = 전역 미필터 센티널)
// - page 파라미터는 항상 삭제(페이지네이션 리셋)
// - router.push 로 URL 갱신 → 서버 컴포넌트 재렌더
```

세 페이지 공통 레이아웃 (`ListPageHero` 아래):
```tsx
<div className="flex items-center justify-between gap-3 my-6">
  <FilterChips .../>   {/* 이번에 FilterBar로 교체 대상 */}
  <SortSelect .../>    {/* 그대로 유지 */}
</div>
```

## 새로 만들 것 / 바꿀 것

### 1. `src/components/common/FilterModal.tsx` (신규)

```ts
interface FilterOption { id: string; label: string }
interface FilterSection {
  key: string;               // URL 파라미터 키: "location" | "barangay" | "type" | "salaryType" | "roomType" | "rentType" | "category" | "condition"
  label: string;              // 섹션 제목 (서버에서 번역된 문자열을 그대로 받음)
  options: FilterOption[];    // "all" 항목은 포함하지 않음 — 모달이 자체적으로 맨 앞에 전체 pill을 붙인다
  dependsOn?: string;         // 세부지역 섹션이면 dependsOn: "location"
}
interface FilterModalProps {
  sections: FilterSection[];
  values: Record<string, string>;                                // 현재 URL 값 (없으면 "all")
  optionsMaps?: Record<string, Record<string, FilterOption[]>>;  // optionsMaps["barangay"][지역id] = 세부지역 옵션 배열
  onClose: () => void;
  isClosing: boolean;
}
```

동작:
- **draft 상태**: `useState(() => ({...values}))`. 이 컴포넌트는 열려 있을 때만 마운트되므로 (`{open && <FilterModal .../>}`) mount 시 1회 초기화로 충분하고, 별도 sync `useEffect`는 필요 없다.
- 섹션마다 `flex flex-wrap gap-2` pill 토글 버튼 목록을 렌더링. 각 섹션 맨 앞에는 항상 "전체" pill(`id: "all"`, 라벨 `Common.filter.all`)이 있다.
- **세부지역(barangay) 섹션 (의존 섹션)**: 옵션은 `optionsMaps.barangay?.[draft.location] ?? []`로 구한다. `draft.location`이 `"all"`이면 pill 대신 안내 문구(`Common.filter.barangayHint`, "지역을 먼저 선택해주세요")를 보여준다. `location` draft가 바뀌면 **같은 `setState` 호출 안에서** `barangay` draft를 `"all"`로 같이 리셋한다. 이 의존 관계는 `dependsOn` 필드 하나로 선언하고, 모달의 리셋 로직과 `FilterBar`의 칩 제거 캐스케이드(아래) 둘 다 이 선언 하나만 참조하도록 한다 — 로직을 두 군데서 따로 하드코딩하지 않는다.
- **푸터** (sticky, MeetupCreateModal 푸터 구조 그대로): "전체 해제"(`Common.filter.clearAll`) 클릭 시 모든 섹션의 draft를 `"all"`로 설정한다(이 시점엔 URL을 건드리지 않는다). "필터 적용"(`Common.filter.apply`) 클릭 시 `updateParams(draft)`를 **모든 섹션 key를 포함해서** 호출한 뒤(선택 해제된 항목도 명시적으로 `"all"`을 넘겨야 URL에서 삭제됨) `onClose()`를 호출한다.
- **닫기(적용 안 함)**: 배경 클릭, 헤더 X 버튼, Escape 키(ConfirmModal 패턴 그대로) — 셋 다 draft를 버리고 그냥 닫는다.
- 열려 있는 동안 `document.body.style.overflow = "hidden"`으로 배경 스크롤 잠금.
- **Portal 사용** (ConfirmModal 방식, MeetupCreateModal의 inline `fixed` 방식이 아님). 이유: `FilterBar`는 페이지 중간(`ListPageHero` 아래)에 위치하므로, 조상 요소에 `transform`/`overflow`가 걸리면 `fixed` 포지셔닝이 깨질 수 있다. `z-100`(배경) / `z-101`(패널)로 ConfirmModal과 동일한 레이어를 쓴다.

### 2. `src/components/common/FilterBar.tsx` (신규, `FilterChips.tsx` 대체)

모달의 열림/닫힘/종료 애니메이션 상태를 소유하고, 트리거 버튼 + 적용된 칩을 렌더링한다.

```ts
interface FilterBarProps {
  sections: FilterSection[];
  values: Record<string, string>;
  optionsMaps?: Record<string, Record<string, FilterOption[]>>;
}
```

- **필터 버튼**: `SlidersHorizontal`(lucide-react) 아이콘 + `Common.filter.button` 라벨 + 활성 필터 개수 뱃지 (0개면 뱃지 숨김).
- **적용된 칩**: `values[key] !== "all"`인 섹션마다 `라벨 ✕` 모양 pill을 렌더링한다.
  - 라벨 조회: `sections.find(s => s.key === key)?.options.find(o => o.id === value)?.label ?? value`
    (barangay처럼 `optionsMaps` 기반 동적 옵션은 애초에 값 자체가 사람이 읽을 수 있는 지명이므로 `?? value` fallback으로 충분함)
  - X 클릭 → `updateParams({ [key]: "all", ...cascade })`. `cascade`는 `dependsOn === key`인 모든 섹션도 `"all"`로 같이 넘긴다 (지역 칩을 지우면 세부지역 칩/파라미터도 같이 사라져야 함).
- **레이아웃**: 기존 페이지의 `<div className="flex items-center justify-between gap-3 my-6">` 안에서 `<FilterBar .../>`(좌측) + `<SortSelect .../>`(우측, `shrink-0` 클래스 추가) 형태를 유지한다.
- **열림/닫힘 상태**: `useState(false)` open 플래그 + `closing` 플래그로 exit 애니메이션 재생 후 `setTimeout`으로 언마운트 (`GoClient`가 `MeetupCreateModal`을 여닫을 때 쓰는 handshake와 동일 패턴 — 해당 파일 참고).

### 3. `src/components/common/ListSearchBar.tsx` (신규)

세 페이지의 `_components/JobFilters.tsx` / `RentalFilters.tsx` / `UsedGoodsFilters.tsx`가 지역 선택을 모달로 넘긴 뒤에는 전부 "텍스트 검색만 하는" 동일 코드가 된다. 하나로 통합:

```tsx
"use client";
import { SearchBar } from "@/components/common/SearchBar";
import { useUrlParams } from "@/hooks/useUrlParams";

export function ListSearchBar({ givenSearch }: { givenSearch: string }) {
  const { updateParams } = useUrlParams();
  return (
    <SearchBar
      givenSearch={givenSearch}
      onSearch={(query) => updateParams({ search: query })}
      className=""
    />
  );
}
```

(참고: 기존 `RentalFilters`는 검색 시 `barangay: "all"`도 같이 리셋했는데, 이제 검색이 지역을 바꾸지 않으므로 이 로직은 필요 없어진다.)

## 행동 변화 (팀 공유 필요)

기존에는 `sessionUser?.region`이 검색바 지역 드롭다운의 기본값으로 쓰였다 (단, 검색을 제출하기 전까지는 목록을 필터링하지 않았음 — 순수 UI 프리필). URL 기반 칩 UI에서는 URL에 없는 값을 칩으로 "적용된 필터"인 것처럼 정직하게 표시할 수 없으므로, 이번 작업에서 이 자동 프리필은 제거한다. 필요하다면 첫 방문 시 `location` 쿼리 파라미터를 서버에서 리다이렉트로 세팅하는 방식으로 별도 추가할 수 있으나, 이번 작업 범위에는 포함하지 않는다.

## 검증 체크리스트

- 정적 검증: `npx tsc --noEmit`, `npm run lint`, `npm run build`
- `npm run dev`로 수동 확인:
  - **`/job`**: 모달에서 지역+근무형태+급여형태 선택 → 필터 적용 → URL에 세 파라미터 반영, 목록 필터링됨. 정렬을 인기순/마감임박순으로 바꿔도 salaryType 필터가 유지되는지 확인(3분기 리스크 지점). 칩 X로 개별 해제. 모달 내 "전체 해제" 후 "필터 적용" → 파라미터 전부 삭제.
  - **`/rental`**: 최신순/인기순 정렬에서도 거래형태(rentType) 필터가 동작하는지(결합 제거 확인 포인트). 지역 선택 시 세부지역 pill이 해당 지역 것만 나타나는지. 지역 draft를 바꾸면 세부지역 draft가 리셋되는지. 지역 칩을 제거하면 세부지역 칩/파라미터도 같이 사라지는지. 가격순 정렬에서도 모든 필터가 유지되는지.
  - **`/usedgoods`**: 4개 정렬(latest/popular/price_asc/price_desc) 전부에서 condition 필터가 동작하는지. 세부지역 cascade는 rental과 동일하게 확인.
  - **모바일 뷰포트**: 모달이 바텀시트로 뜨는지(`slideInUp`/닫을 때 `slideOutDown`), 열려 있는 동안 body 스크롤이 잠기는지, 배경 클릭/Escape로 닫으면 draft가 버려지고 URL에 반영 안 되는지.
  - **검색바**: 세 페이지 모두 텍스트 입력만 남고 지역 버튼/구분선이 없는지. 메인 페이지의 `MainSearchBar`는 별개 컴포넌트라 영향이 없는지 확인.
