## 1. 잘못된 가설 먼저 배제

팀원 진단은 "07.06 preload 커밋(3b38b46)의 `fill` 이미지가 썸네일을 덮고, 64×64 썸네일이 부모 `position: relative` 부재로 렌더링 안 됨"이었다. 코드 확인 결과 사실과 달랐다.

| 주장 | 확인 결과 |
|---|---|
| preload `fill` 이미지가 썸네일 영역을 덮음 | preload 이미지는 `invisible`(visibility: hidden) + `pointer-events-none`이라 시각적으로 아무것도 덮을 수 없음 |
| `width={64} height={64}` 썸네일이 렌더 안 됨 | 해당 코드가 소스에 존재하지 않음 (옛 문서에만 있음). 고정 크기 이미지는 부모 `relative`가 필요 없음 — `fill`만 필요 |
| 캐러셀 썸네일에 `relative` 부재 | `ImageCarresel.tsx` 썸네일은 이미 `relative` 클래스가 있는 버튼 안에 `fill`로 렌더링 중 |

결정적으로 **CSS 문제라면 개발 서버에서도 똑같이 깨져야 하는데 배포에서만 깨졌다.**

## 2. 진단 과정

배포 서버의 이미지 최적화 엔드포인트를 curl로 직접 호출했다.

```
GET https://kanto-iota.vercel.app/_next/image?url=<loremflickr URL>&w=640&q=75
→ HTTP 402 Payment Required
   X-Vercel-Error: OPTIMIZED_IMAGE_REQUEST_PAYMENT_REQUIRED
```

**Vercel 무료(Hobby) 플랜의 이미지 최적화 한도 초과** 응답이다. 같은 실제 유저 이미지로 교차 검증하니 원인이 확정됐다.

| 요청 | 결과 |
|---|---|
| 실제 유저 이미지 `w=640` (이미 변환·캐시된 크기) | **200 OK** |
| 같은 이미지 `w=828`, `w=1080` (캐시 안 된 크기) | **402** (X-Vercel-Cache: MISS) |

DB의 이미지 호스트 분포도 증상과 정확히 일치했다.

| 호스트 | 장수 | 대상 |
|---|---|---|
| `loremflickr.com` (외부) | 228 | 목업 게시물 |
| `*.supabase.co` (스토리지) | 184 | 실제 유저 게시물 |

## 3. 원인 정리

1. **트리거**: 07.06 커밋 `3b38b46`("이미지 렌더링 느린 에러 해결")이 모든 카드 이미지에 `loading="eager"`를 걸어 lazy 로딩을 제거 → 방문자마다 목록 페이지의 전체 이미지 × 여러 너비(w) × avif/webp 포맷 변환 요청이 즉시 발생 → 한도 급속 소진.
2. **목업만 깨진 이유**: 한도 초과 후에도 이미 캐시된 변환본은 계속 서빙된다. 실제 유저 이미지는 자주 보던 크기가 캐시돼 있어 정상, 목업 228장은 캐시 안 된 변환이 많아 402 → `onError` → fallback으로 대체.
3. **개발 서버가 정상인 이유**: `next dev`는 로컬 sharp로 최적화하므로 Vercel 한도와 무관.

## 4. 수정 내역

### 4-1. 402 우회 — 커밋 `ff8df95`

- `next.config.ts`: `images.unoptimized: true` — `/_next/image`를 우회해 원본 직접 서빙 (한도 리셋 후 재검토)
- `ContentCard.tsx`: 카드 이미지 일괄 `loading="eager"` 제거(lazy 복원) — 한도 소진의 원인이자, 원본 직접 서빙 시 외부 서비스 rate limit 재발 방지. 호버/터치 시 인접 이미지 프리로드(원래 "느리다" 문제의 해결책)는 유지

### 4-2. 목업 이미지를 자체 스토리지로 이전 — 커밋 `334d652`

외부 이미지 의존 자체를 제거하기 위해 `scripts/migrate-mock-to-user-uploads.ts`로 실사용자 업로드와 동일한 규칙으로 전량 이전했다.

| 대상 | 이전 경로 (실사용자 규칙과 동일) |
|---|---|
| 게시물 이미지 (중고 71건 / 렌탈 29건 / 구인 35건, 263장) | `images/{userId}/{postId}/{timestamp}.webp` |
| 구인 로고 35개 | `images/logos/{userId}/{postId}.webp` |
| 목업 아바타 100개 (`seed/avatars/{id}.webp`) | `images/avatars/{userId}/profile` |

- webp 변환(quality 0.8), `cacheControl: 31536000` — 앱 업로드 로직과 동일
- loremflickr가 키워드 3개 이상 조합에서 500을 반환하는 이슈 → "키워드 축소 → picsum 폴백" 재시도로 36장 실패분까지 전량 회수
- 이전 완료 검증 후 `seed/` 폴더 삭제 (참조 0건 확인)

### 4-3. 폐기 스크립트 삭제 — 커밋 `f04012e`

- `fix-images-relevant.ts`: 재실행 시 게시물 이미지를 다시 loremflickr로 교체 → 사건 재발
- `upload-images-to-storage.ts`: 재실행 시 정리한 `seed/` 폴더 구조를 재생성
