# Kanto 18차 리뷰 (2026-07-04)

마감 임박 시점이라 오늘부터는 관점을 하나 더 얹습니다. 이 레포는 이제 발표용을 넘어 **곧 외부에 공개돼 여러분 이력서에 걸릴 물건**입니다. 그 눈으로 다시 훑어봤습니다.

## 총평

5조 중 코드·문서 위생이 가장 앞서 있습니다. `docs/` 아래 문서가 27개나 쌓여 있고, `console.log`는 dev 가드가 걸린 1건뿐이고, TODO도 안 남아 있고, `.env.local`도 git에 안 올라가 있습니다. SEO 인프라(sitemap·robots·OG·JSON-LD)도 5조 중 유일하게 완비돼 있고요. 이 정도면 이력서에 걸었을 때 "코드를 아무렇게나 두지 않는 팀"이라는 인상을 충분히 줄 수 있습니다.

다만 취업 레포 관점에서 지금 제일 위험한 건 **anon 키로 `users` 테이블 전체가 읽힌다**는 점입니다. 공개 저장소가 되는 순간 이건 코드만 봐도 재현 가능한 레시피가 되고, 관리자 이메일·전화번호가 그대로 노출됩니다. 완성도가 높은 프로젝트일수록 이런 구멍 하나가 신뢰를 통째로 깎아먹으니, 이번 리뷰의 최우선 순위로 다시 올립니다.

## 지난 리뷰 반영 현황

17차에서 남긴 항목들을 하나씩 다시 확인했습니다.

- **소프트딜리트 중고글 상세 노출** → **해결**. `src/services/usedGoods/usedGoods.ts:104`에 `.neq("posts.status", "deleted")`가 들어가 있는 걸 확인했습니다. 15차 때부터 이어지던 문제인데 이제 완전히 막혔습니다.
- **관리자 일괄처리 `requireAdmin` 누락** → **해결**. `src/app/(admin)/admin/posts/_actions/bulkPostActions.ts`를 열어보니 27행·56행·69행 각 함수 첫 줄에 `await requireAdmin()`이 들어가 있습니다. bulk 계열만 빠져 있던 구멍이었는데 이제 다른 서버 액션들과 동일한 패턴으로 맞춰졌습니다.
- **채팅 "rentals" 오타** → 이건 다시 보니 지적이 잘못됐습니다. `src/app/api/chat/[id]/route.ts:69`의 `post_type === "rental"`은 단수형이 맞는 표기였고, sitemap이나 서비스 코드 전반과 일치합니다. 지난번 지적을 취소합니다.
- **CRON cleanup fail-open** → **해결**. `src/app/api/posts/cleanup/route.ts:13`에서 시크릿이 없거나 `Bearer` 토큰이 안 맞으면 401을 반환하도록 바뀌어 있어 fail-closed로 정상 동작합니다.
- **[필수·보안] anon `users` 테이블 PII 전체 노출** → **미해결 (7회 연속)**. anon(publishable) 키로 `GET /rest/v1/users?select=id,email,role,phone`을 직접 호출하니 HTTP 200과 함께 124행이 그대로 내려옵니다. `role` 필터를 걸면 관리자 계정의 이메일·전화번호까지 골라서 볼 수 있고요. 같은 방식으로 `messages`·`chats`·`transactions`는 0행만 나오는 걸로 봐서 RLS 자체는 다른 테이블에서 정상 동작 중이라, `users` 테이블 하나만 정책이 빠진 상태로 보입니다. 이미 `usedGoods.ts:102`에서 공개용으로 `public_profiles` 뷰를 쓰고 있으니, 방향은 맞게 잡은 상태에서 원본 `users` 테이블의 anon 접근만 닫으면 됩니다. 구체적인 방법은 가이드 문서에 정리해 뒀습니다.

## 이 조가 취업 레포로 먼저 할 3가지

① **README에 라이브 데모 링크·서비스 스크린샷·조원별 기여 섹션**이 아직 없습니다. 팀원 표는 있는데 역할이 "팀장/팀원"으로만 적혀 있어서, 저장소만 봐서는 누가 무엇을 만들었는지 전혀 안 보입니다. 공통으로 정리해 둔 `202607042124-취업레포-가이드.md`에 방법을 자세히 적어뒀으니 참고해서 채워주세요.

② **anon `users` PII 노출을 공개 전에 반드시 닫아야 합니다.** 위에서 설명한 것처럼 이건 이력서 레포가 공개되는 순간 그대로 재현 가능한 보안 사고입니다. 마감 전에 가장 먼저 처리할 항목으로 둡니다.

③ **eslint 14 error가 CI 게이트에서 빠져 있어서 계속 머지되고 있습니다.** `.github/workflows/ci.yml`을 보면 `tsc --noEmit`과 `npm run build`만 스텝으로 들어가 있고 `npm run lint`가 없습니다. 그래서 `react-hooks/purity` 같은 규칙 위반이 계속 통과되고 있는데요, 지금 당장 error를 0으로 만들 필요는 없더라도 CI에 lint 스텝 하나 추가하는 건 몇 줄이면 되는 일이라 이번 주 안에 넣어두면 좋겠습니다.
